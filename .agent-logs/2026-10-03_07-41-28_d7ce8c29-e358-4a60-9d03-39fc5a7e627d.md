3. **Other hardening I added to the reset flow:**
   - The OTP is stored hashed and expires after 10 minutes.
   - You get 5 attempts.

4. **Refresh tokens:** they're random strings, and the database only stores their HMAC. Each refresh swaps in a new token. If an old token is ever reused, every session for that user is revoked, because reuse means it leaked.
5. **bcrypt:** 10 rounds takes roughly 50â€“80ms per hash. bcrypt only reads the first 72 bytes of a password, so passwords are capped there. If you change `BCRYPT_ROUNDS` later, each user's hash is redone at the new cost on their next login.
6. **Gmail sending:** you need 2-step verification on, plus a Google App Password in `OTP_EMAIL_APP_PASSWORD`. Until that's set, the OTP is printed to the server log, which is fine for development. Gmail also caps daily sends, so use something like Resend or SES before real users.
